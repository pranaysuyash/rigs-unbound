Accessibility Statement

Rigs Unbound aims to be understandable, operable, and readable in the browser. This page summarizes what already works, what still needs validation, and where to send feedback.

Last updated: 2026-07-29

Current accessibility posture

  • Keyboard access reaches the main flow.
  • A skip link jumps to the playable world.
  • Focus styles are visible and consistent.
  • Semantic buttons and live status regions are used in the shell.
  • The shell stays readable at narrow/mobile widths without horizontal overflow.
  • Bootstrap, save, and profile text are visible in the browser.
  • The live runtime includes fallback-aware browser behavior.
  • The public statement still works with JavaScript disabled.
  • The public statement stays readable at 200% browser scale without horizontal overflow.
  • Reduced-motion browser settings are honored in the shell.
  • The world clock stays passive text so the shell does not chatter on time updates.
  • Live announcement surfaces now speak as full phrases in the shell (current objective, loading, save, quality, notification, and control lesson).
  • Terse touch controls now expose clearer spoken names in the shell.

What is still being improved

  • Spoken screen-reader narration for the public shell.
  • Clearer public feedback and issue-reporting guidance.
  • Keeping the statement current as the evidence evolves.

Known gaps

The shell is structurally accessible, but not every experience has been validated with manual assistive-technology testing yet. The loading story is still textual rather than a dedicated progress bar, though the statement page itself remains readable when JavaScript is disabled and at 200% browser scale.

Feedback

If you find an accessibility issue, please record it in the project docs or open the relevant review surface so it can be tracked alongside the other browser-delivery evidence.

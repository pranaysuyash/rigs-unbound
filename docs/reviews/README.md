## What belongs here

- acceptance records for runtime slices;
- evidence summaries that prove or reject a claim;
- decision-provenance audits;
- launch/comms approval surfaces;
- post-hoc clarifications that need a durable home.
- public asset promotion reviews and approval decisions.

## Open browser-delivery trust gaps

These reviews stay open until the public shell can explain both loading/policy
state and persistence/recovery state in a player-facing way:

- [Visible Input and Accessibility Profile Issue Review](VISIBLE_INPUT_ACCESSIBILITY_PROFILE_ISSUE_REVIEW_2026-07-26.md)
- [Save Status Announcement Issue Review](SAVE_STATUS_ANNOUNCEMENT_ISSUE_REVIEW_2026-07-26.md)

Current browser proof now shows both contracts in the rendered shell, but the
remaining open step is stronger assistive-tech validation rather than another
source-level contract rewrite.

The browser-delivery policy notes and the shell-profile owner contract remain
the canonical bridge docs that explain why these are separate player-facing
contracts rather than one merged policy.

Supporting evidence for the current browser-accessibility state is recorded in
[Shell Accessibility Evidence](../research/SHELL_ACCESSIBILITY_EVIDENCE_2026-07-28.md).

## Current posture

The reviews folder is intentionally not a second source of truth. Each review
should point back to the canonical decision, contract, or package index that it
depends on.

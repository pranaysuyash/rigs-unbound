# Deterministic kernel probe — results

Date: 2026-07-25
Status: verified experiment; not a production-runtime decision

## Outcome

The probe supports the narrow architecture claim it was built to test:

- the same tractor ID and state cross farming, defense, and time-trial modes;
- the simulation produces identical results for equivalent elapsed time split
  into different frame chunks;
- browser automation can drive and inspect the game through
  `advanceTime(ms)` and `render_game_to_text()`;
- presentation remains an adapter over the kernel rather than the source of
  gameplay state.

This does **not** prove final handling, fun, multiplayer determinism, production
rendering, mobile performance, or asset-pipeline suitability.

## Evidence

### Tier 2 — targeted checks

Commands:

```bash
npm run typecheck
npm test
npm run test:coverage
```

Observed results:

- strict JavaScript type checking passed;
- 7 of 7 kernel tests passed;
- coverage: 94.56% lines, 77.46% branches, 95.83% functions.

The tests cover seed reproducibility, elapsed-time chunk invariance, all
activity transitions, persistent vehicle state, failure behavior, and the text
inspection contract.

### Tier 4 — browser behavior

The repository's browser-game workflow client completed two scripted paths:

1. farm to defense;
2. farm through defense to time trial.

Both runs produced screenshots and structured state under
`artifacts/browser/`. The time-trial run reached tick 703 with the original
tractor ID, 55% condition, three scrap, and three harvested crops. The client
reported no page or console errors.

An additional interactive Browser pass checked:

- desktop first-play overlay and active HUD at 1200×892;
- narrow layout and touch controls at 390×844;
- live touch input moving the tractor;
- a clean console after reload.

That pass found and closed two issues:

- a missing favicon caused a browser-console 404;
- the narrow start panel, HUD, and touch controls overlapped.

## Three-pass review

### Pass 1 — immediate correctness and completeness

Checked fixed-step progression, transition conditions, persistent state,
failure behavior, automation hooks, desktop visuals, and mobile controls.
Corrected a start-up temporal-dead-zone risk, a route drawn in the wrong modes,
an unreadably small tractor/crop scale, the favicon error, and narrow-layout
overlap.

### Pass 2 — architecture and long-term viability

Confirmed this is a non-production comparison fixture under `experiments/`.
The kernel owns gameplay state; the Canvas 2D adapter only renders it. No
production engine, renderer, or asset format is selected by this work.
Promotion would require an explicit migration into the canonical root runtime,
not a second editable production kernel.

### Pass 3 — rule compliance and supervision readiness

Rechecked the requested deterministic hooks, browser-game workflow, preserved
the concurrent root implementation untouched, and kept paid/private asset
sources outside the experiment. The evidence is durable, while claims remain
limited to the behaviors actually observed.
